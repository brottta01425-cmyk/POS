# Brottta POS v18.5 Notifications

## In-app messages
Transient POS messages now automatically disappear after 3 seconds. This includes the message shown after deleting/cancelling an unpaid bill.

## Android app notifications
For Cashier, Chef and Waiter roles, Brottta requests Android notification permission.

When the app is backgrounded/switched away but its process is still active:
- Chef: notification when a new Kitchen order arrives.
- Waiter: notification when an item becomes READY.
- Cashier: notification when a bill changes to BILL_REQUESTED.

When the POS is visible, the existing in-app sound behavior remains.

Android 13+ requires Notifications permission. The app requests it automatically.

## Important Android limitation
These are local notifications generated by the running Brottta app. Android may suspend network/realtime activity after the app has been in the background for a long time, and no local app can receive Supabase changes after it is force-stopped. Guaranteed notifications while fully closed require a remote push system such as Firebase Cloud Messaging / OneSignal / a Supabase Edge Function push workflow.

## Build
For an existing Android project:
1. npm install
2. npm run android:sync
3. npm run android:open
4. Rebuild the signed APK using the same keystore.
